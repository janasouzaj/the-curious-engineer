# Learning Resources

This document contains the curated resources for the 24-month journey.

> Use a small number of strong primary resources deeply instead of collecting dozens of shallow ones.

---

# Resource Hierarchy

When learning a topic, prioritize:

1. Primary book / canonical text
2. Official documentation
3. Source code / real examples
4. Engineering blogs
5. Conference talks
6. Podcasts / interviews
7. Hands-on labs
8. Real projects

For troubleshooting, start with the system and evidence, then consult documentation.

# Resource Selection Rules

Before adding a resource, ask:

- Does it explain something the current resource does not?
- Is it primary or authoritative?
- Will I actually use it?
- Does it support a current module?
- Is the content still relevant?

The resource list should remain small enough to follow.

---

# Guiding Principle

> Tools change. Fundamentals compound.

The purpose of this resource list is to support the capability being built in each module, not to complete every item.
