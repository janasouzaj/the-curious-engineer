# The Curious Engineer

> I'm not building a resume. I'm documenting my evolution as an engineer.

**The Curious Engineer** is my 24-month learning journey toward **DevOps Engineering with a specialization in Observability**.

This repository is not a collection of courses or certificates. It is a public engineering notebook where I study the foundations behind the systems I work with, experiment, break things, troubleshoot them, build small projects, document what I learn, and share the evolution.

The goal is simple:

**understand systems deeply enough to operate, observe, troubleshoot, automate, and eventually design them.**

---

## North Star

My target is not to become "the person who knows the most tools."

I want to evolve through this path:

```text
DevOps Engineering
        ↓
DevOps + Observability
        ↓
Observability Engineering
        ↓
Senior / Platform & Observability Engineering
        ↓
Staff / Principal Engineering
        ↓
Observability / Platform Architecture
```

The exact role may evolve. The engineering foundation is the constant.

---

## Learning Philosophy

My learning loop is:

**Learn → Experiment → Break → Investigate → Build → Document → Share → Revisit**

I do not want to memorize commands without understanding them.

I prefer to know:

- why a tool exists
- what happens underneath it
- what assumptions it makes
- how it fails
- how to troubleshoot it
- how to measure whether a solution is actually better

> Tools change. Fundamentals compound.

## How Progress Is Measured

A module is not "complete" because I finished reading a book.

A module is complete when I can demonstrate evidence of understanding through some combination of:

```text
Concepts understood
      +
Labs completed
      +
Problems intentionally broken
      +
Troubleshooting performed
      +
Code / configuration written
      +
Documentation produced
      +
Technical explanation given
```

The goal is **capability**, not checklist completion.
