# 24-Month Timeline

**Start:** October 2026  
**Target completion:** September 2028  
**Recommended workload:** 8–10 focused hours per week

This timeline is deliberately simple: **one core module per month**.

Depth matters more than speed.

---

# Weekly Learning Cadence

| Day | Focus |
|---|---|
| Monday | Book / primary reading |
| Tuesday | Official documentation |
| Wednesday | Hands-on lab |
| Thursday | Notes, code or diagrams |
| Friday | Technical reflection / LinkedIn |
| Saturday | Optional visual content / Instagram |
| Sunday | Review, self-assessment and next-week planning |

The schedule is a default, not a constraint. Work commitments and real incidents can change the week.

---

# Monthly Learning Loop

```text
Week 1
Understand the concepts

Week 2
Read official documentation and inspect real examples

Week 3
Build and break a lab

Week 4
Document, review, explain and consolidate
```

---

# Monthly Deliverables

Minimum monthly output:

- 1 completed learning module
- 2–4 focused labs or experiments
- 1 troubleshooting scenario
- 1 project / integration update
- technical notes
- 1 deeper Medium article
- weekly LinkedIn reflection when the topic produces something worth sharing

Quality is more important than publishing volume.

# Content Cadence

### GitHub

The repository is the source of truth for technical work.

### LinkedIn

Approximately one useful technical reflection per week, when there is something meaningful to share.

### Instagram

One visual post per week when the topic lends itself to diagrams or explanations.

### Medium

One substantial article per month, consolidating the strongest learning and experiments from that month.

Content is derived from the engineering work. Publishing volume is not a goal by itself.

---

# Quarterly Reviews

Every three months, review:

- What concepts are now clear?
- What is still fuzzy?
- Which labs exposed weak foundations?
- Which tools am I using mechanically rather than understanding?
- What evidence exists in the repository?
- What should change in the roadmap?

---

# Rule for Falling Behind

If a month is missed, do not compress two modules into one merely to recover the calendar.

Instead:

1. update `NOW.md`
2. record the reason
3. resume from the last unfinished module
4. adjust the target month if necessary

Consistency matters more than the original date.
